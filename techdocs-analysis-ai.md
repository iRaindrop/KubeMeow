# TechDocs Analysis AI Prototyping

This document describes a structure of the predefined prompt files to use in Copilot Enterprise in Visual Studio Code. The objective is to find optimal workflows for incorporating AI output into TechDocs analysis of CNCF project documentation, contributor documentation, and website and infrastructure.

The location is the root directory in a GitHub repository of a CNCF project undergoing an analysis. [KubeVirt](https://kubevirt.io/user-guide/) is the project for this Analysis. See the latest updates on the [preview](https://deploy-preview-358--cncf-techdocs.netlify.app/).

## Current process

Writers refer to the [Howto](https://github.com/cncf/techdocs/blob/main/docs/analysis/howto.md) document, along with the [Criteria](https://github.com/cncf/techdocs/blob/main/docs/analysis/criteria.md) specifications to create a report based on the [analysis.md](https://github.com/cncf/techdocs/blob/main/docs/analysis/templates/analysis.md) template.

There is an open [PR - 357](https://github.com/cncf/techdocs/pull/357) on the analysis templates to gather feedback for updates.

The analysis template has three sections:
- Project Documentation
- Contributor Documentation
- Website and Infrastructure

Each section has a number of analysis areas, such as Information Architecture in Project Documentation. Each area has a group of questions, based on the Criteria specification, for the analysis writer to research and answer. The analysis template provides locations for the writer to add content in the following places:
- A comment overview for each section.
- Answers to criteria questions in each area.
- Recommendations for an area.

The template was designed to be flexible and can accommodate variances. The analysis writer can usually get a good understanding of how to complete the analysis within two to three weeks. Then it's a matter of meeting with the team to gather answers and feedback. The writer typically doesn't have enough information to complete the website and infrastructure section.

## AI involvement

The capabilities and benefits of using AI for the analysis is striking. And predictably, so rises the effort and questions regarding the evaluation of AI tools, options, and logistics to process AI generated content into the template.

At first thought, the analysis should be formatted to provide a distinction between human analysis content and the content generated by AI. But it soon becomes apparent that AI content reviewed by humans for accuracy negates that distinction. Nevertheless, the writers must first be familiar enough with the content and the project and record their observations and analysis and later compare it to AI.

The AI tooling provided by Copilot Enterprise and predefine prompts can process AI generate content in two ways:
- The [copilot-instructions](https://github.com/iRaindrop/KubeMeow/blob/main/copilot-instructions.md) file provides instructions for the AI agents with predefined prompts, content style, repository, conventions, and notes. This is a powerful file as its continuously tweaked to optimize the AI output. 

- The [Predefined prompts](https://github.com/iRaindrop/KubeMeow/blob/main/copilot-instructions.md#predefined-prompts) provide re-usable commands for the Copilot CLI prompt to gather analysis to meet the needs of the template and to provide output for answers, comments, ratings, and recommendations. These files also contain agent instructions such a the desired number of paragraphs and how to format the output, e.g. bulleted lists with indented paragraphs.

Having predefined prompts does not mean that the AI output is the same for the same prompt, but they can be similar. Affecting the output are any existing AI output files. In fact, some predefined prompts may depend on existing files, as in the case of a recommendations predefined prompt that existing comment output.

There are a lot of variables to refine, but the volume and format of the AI output is controllable and that alleviates the need for processing text by the writer. The writer then has more time to evaluate the output and refine instructions in the copilot-instructions file or in the predefined prompt files.

The TechDocs [issue](https://github.com/cncf/techdocs/blob/main/docs/analysis/templates/issue.md) and [issue-list](https://github.com/cncf/techdocs/blob/main/docs/analysis/templates/issues-list.md) templates is another analysis that could be serviced by predefined prompts.

## Template and automation

After the writer has run all predefined prompts for the analysis, creating 40 to 50 output Markdown files, the content in these files must be copied and pasted into the correct locations in the analysis.md template. This is a laborious process so having the template text and the AI output programmatically assembled is a worthy solution. Asked about it, AI suggested the following tools layout:

| Tool or resource | Function |
| --- | --- |
| assemble.py | Python app to load configurations, and map and render content in analysis.md file. |
| config.yaml | Project metadata, maturity, author, and URLs. |
| mapping.yaml | Associates the AI output with the corresponding section in the template. |

The predefined prompt process can work with the template's structure, but updates to the template could define a tighter mapping to the AI output files.

As the writer refines the AI though the copilot-instructions file and prompt files, the system should be flexible to handle precise updates to complete regenerations.
